工作原理

观察 — 思考 — 行动，单步推进

小X 每一轮只做一件事：看清当前界面，规划下一个动作，执行后立刻校验。错了就回退重规划，对了再走下一步。

01

感知

截图 + OCR 文字、通用元素识别、UI 层级清洗，拿到带坐标的可交互元素。

→
02

规划

结合目标与历史，思考下一步，只输出一个动作；必要时先加载技能获取经验。

→
03

执行

实机模式下先在真机执行，成功才落入画布；失败把设备真实报错喂回自愈。

→
04

校验

重新截图确认界面变化；没达预期就回退删除错误节点，重新感知规划。

最终留在画布上的，都是经过实机验证、确实有效的步骤 — 一条可复用、可再次运行的自动化工作流。

快速开始

分钟级上手

开发模式一条命令启动；生产包跨平台打包发布。

# 克隆仓库
git clone https://github.com/wieszheng/openx.git
cd openx

# 安装依赖
npm install

# 启动开发模式（热更新）
npm run dev
# 构建 macOS dmg / pkg
npm run build:mac

# 产物输出至 dist/ 目录
# 构建 Windows exe / nsis 安装包
npm run build:win

# 产物输出至 dist/ 目录
# 构建 Linux AppImage / deb
npm run build:linux

Agent & 工具包配置

环境变量

智能编排需配置大模型 API（在应用「设置」中填写 Key / BaseURL / 模型）；设备工具路径可通过环境变量覆盖。

大模型 API在应用设置中配置 OpenAI 兼容接口的 API Key / BaseURL / 模型，驱动小X 智能编排（默认适配通义千问等）
OPENX_ADB_PATH自定义 adb 路径，缺省使用系统 PATH 中的 adb
OPENX_HDC_PATH自定义 hdc 路径，缺省自动查找 DevEco Studio SDK
OPENX_SCRCPY_SERVER_PATHscrcpy-server.jar 路径，屏幕镜像与录屏功能必需
